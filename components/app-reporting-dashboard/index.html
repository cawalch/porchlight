Pattern

Reporting dashboard

A Porchlight-native analytics workspace composition for report controls, saved views, KPI stats, chart shells, insights, and breakdown tables.

stableSince 0.9.0

Open full example →
On this page
  1. Structure
  2. Semantic HTML
  3. Guidance
  4. Preview

Use this composition for product analytics, revenue reports, operational scorecards, and executive summaries. It combines existing Porchlight primitives without adding dashboard-specific CSS.

Structure

  • .pl-c-page-header for report title, date range, refresh, and export actions.
  • .pl-c-saved-views and .pl-c-query-bar for saved report views and active filters.
  • .pl-c-tabs for summary, acquisition, retention, or forecast views.
  • .pl-l-grid with .pl-c-card[data-surface="app"] and .pl-c-stat for KPI tiles.
  • .pl-c-chart for app-owned SVG, Canvas, or image charts with legends and fallback data.
  • .pl-c-table-wrap and .pl-c-table for channel, segment, or cohort breakdowns.
  • .pl-c-empty for insight, no-data, loading, or restricted-report states.

Semantic HTML

<section aria-labelledby="revenue-report-title">
  <div class="pl-c-page-header">
    <div class="pl-c-page-header__heading">
      <h1 class="pl-c-page-header__title" id="revenue-report-title">
        Revenue performance
      </h1>
      <span class="pl-c-page-header__subtitle">May 1-31, 2026</span>
    </div>
    <div class="pl-c-page-header__actions">
      <label class="pl-c-field">
        <span class="pl-u-sr-only">Start date</span>
        <input class="pl-c-field__control" type="date" value="2026-05-01" />
      </label>
      <button class="pl-c-button" data-variant="secondary">Export CSV</button>
    </div>
  </div>

  <nav class="pl-c-saved-views" aria-label="Saved report views">
    <span class="pl-c-saved-views__label">Views</span>
    <ul class="pl-c-saved-views__list">
      <li class="pl-c-saved-views__item">
        <button class="pl-c-saved-views__button" aria-current="true">
          Executive <span class="pl-c-saved-views__count">12</span>
        </button>
      </li>
    </ul>
  </nav>

  <section
    class="pl-c-chart"
    aria-labelledby="trend-title"
    aria-describedby="trend-description"
  >
    <header class="pl-c-chart__header">
      <div>
        <h2 class="pl-c-chart__title" id="trend-title">Revenue trend</h2>
        <p class="pl-c-chart__description" id="trend-description">
          Recurring revenue and forecast by week.
        </p>
      </div>
    </header>
    <div class="pl-c-chart__plot" role="img" aria-label="Revenue trend chart">
      <!-- App-owned SVG, Canvas, or image. -->
    </div>
  </section>
</section>

Guidance

Keep report controls as real form fields with labels. Saved views should be buttons when they mutate the current report state, or links when they navigate to persisted URLs. Give every chart a heading, description, useful plot label, legend, and table fallback for source data. Use <time> for generated-at and range labels, and align numeric table cells with data-align="end".

For loading, empty, and error cases, keep the region in place and swap the chart plot or insight panel to a .pl-c-empty or .pl-c-chart[data-state] state. Announce result-count changes from app code with an aria-live region.
