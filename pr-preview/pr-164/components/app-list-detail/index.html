Pattern

List/detail workspace

A Porchlight-native app composition for queues, records, inspectors, and split-pane detail workflows.

stableSince 0.9.0

Open full example →
On this page
  1. Preview
  2. Semantic HTML
  3. Guidance

Use this composition when users need to scan a queue, filter it quickly, and keep the selected record visible while they review details or take action. It combines the app shell, nav, toolbar, data table, split pane, badges, skeletons, empty state, drawer, and command palette patterns without adding new component CSS.

Preview

Open the list/detail workspace preview.

Semantic HTML

Keep the shell regions explicit:

<div class="pl-l-app-shell">
  <header class="pl-l-app-shell__topbar pl-c-toolbar">...</header>
  <aside class="pl-l-app-shell__sidebar">
    <nav class="pl-c-nav" aria-label="Primary">...</nav>
  </aside>
  <main class="pl-l-app-shell__main">...</main>
</div>

Place the list and inspector in a split pane:

<section
  class="pl-c-split-pane"
  data-orientation="horizontal"
  data-collapse="stack"
>
  <section class="pl-c-split-pane__pane pl-c-split-pane__pane--start">
    <div class="pl-c-toolbar">
      <label class="pl-c-field">
        <span class="pl-u-sr-only">Search requests</span>
        <input class="pl-c-field__control" type="search" />
      </label>
      <button class="pl-c-button">Filter</button>
    </div>
    <div class="pl-c-table-wrap">
      <table class="pl-c-table">
        ...
      </table>
    </div>
  </section>

  <div
    class="pl-c-split-pane__separator"
    role="separator"
    aria-orientation="vertical"
    aria-valuemin="35"
    aria-valuemax="70"
    aria-valuenow="58"
    tabindex="0"
  ></div>

  <aside
    class="pl-c-split-pane__pane pl-c-split-pane__pane--end"
    aria-label="Selected request"
  >
    <header class="pl-c-split-pane__header">...</header>
    <div class="pl-c-split-pane__pane-inner">...</div>
  </aside>
</section>

Use a real table when records are tabular. Put the primary action in the first cell as a button or link, apply aria-selected="true" to the selected row, and keep status in .pl-c-badge. When there is no selected record, render .pl-c-empty in the detail pane. When the list or detail pane is fetching, render .pl-c-skeleton placeholders in the region that is waiting.

Guidance

  • Keep filters in .pl-c-toolbar directly above the table or list.
  • Use .pl-c-split-pane for persistent detail panes and .pl-c-drawer for secondary filter or edit surfaces.
  • Give each pane an accessible name and make scrollable panes focusable when they contain long non-interactive content.
  • Keep row activation separate from bulk-selection checkboxes and disclosure controls.
  • Let app JavaScript own search, selection, saved split sizes, and drawer form behavior.
