Guides

Task-oriented guides for installing, theming, composing, and extending Porchlight.

  • Why Porchlight: A native-CSS design system for dense, keyboard-first product UI, and an honest comparison with Bootstrap, Tailwind and shadcn, Pico, DaisyUI, Bulma, and Radix Themes.
  • Getting started: Install Porchlight, import only the CSS you need, and set up the cascade layer for host overrides.
  • HTMX, Alpine, and CSS Modules: Use Porchlight in server-rendered HTML, HTMX fragments, Alpine islands, and apps with locally scoped CSS.
  • Enterprise Integration & Upstream Recipes: Production guide for enterprise SaaS teams: size budgets, 4 HTMX patterns, layer coexistence, dialog/popover reference, hashed embedding, dense primitives, and fallback floors.
  • Size budget & payload: Production size budgets, Brotli and Gzip payload tables, and core + N component recipes.
  • Architecture and layer model: How Porchlight is layered, and how host applications override it.
  • Naming migration: Update pre-namespace Porchlight markup to the collision-safe public CSS API.
  • Cascade layering and coexistence: Deep-dive into Porchlight's nine cascade layers, layer precedence rules, and coexistence recipes with Tailwind, Bootstrap, and CSS Modules.
  • Layout and page building: Use Porchlight's layout primitives, app shell, and container-query sidebar to compose responsive SaaS pages.
  • Composition recipes: Model-friendly recipes for composing Porchlight app shells, dashboards, data regions, settings pages, and dense admin views.
  • Modern SaaS and LLM Design Guide: Architecture rules, component selection trees, responsive search/filter patterns, and anti-hallucination guardrails for building modern 2026 SaaS applications.
  • Desktop apps and installed PWAs: Add a native-feeling titlebar and window drag region to Electron, Tauri, and Window Controls Overlay PWAs with Porchlight's desktop shell.
  • Theming: Override design tokens, create brand themes, and understand the light-dark() color system.
  • Utilities: A small, finite set of single-purpose helpers for accessibility, layout, and typography. Not a utility-first framework.
  • Dialog and Popover reference: Architectural reference comparing native dialog and the Popover API, focus trapping, top layer mechanics, and anchor positioning.
  • Browser support: Required CSS capabilities, progressive fallbacks, and the limits of Porchlight's browser coverage.
  • Enhancements: Progressive enhancement features gated behind @supports. The framework works without them; they add polish where the browser supports them.
  • Deprecation policy and SemVer stability: SemVer stability contract, public API scope, deprecation grace periods, and breaking change guarantees.
